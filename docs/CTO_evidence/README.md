# CTO Evidence

This directory is generated by `scripts/quality/collect_cto_review_evidence.py`. It is a point-in-time, machine-readable evidence surface; do not edit the files by hand. `cto_evidence_bundle.json` is the canonical bounded contract for reviewers and future release-evidence consumers.

The canonical bundle separates an optional declared workload run from `historical_state`. Without `--run-manifest`, it explicitly reports a historical system snapshot and does not assign a workload disposition. With a run manifest, the executive summary leads with its open-taxonomy run type, exact tested SHA, immutable subjects, required criteria, outcomes, run-scoped measurements, and limitations. Historical SQLite and artifact telemetry stays in its own namespace and never contributes to run totals or criteria.

Run manifests use schema version `1.0`, repository-relative hash-pinned source paths, full tested SHAs, immutable subject hashes, declared scope, and optional comparison identities/invariants. Start and end timestamps are timezone-aware and supplied together; use `null` for both when the producer did not retain them. The projector always requires `exact_repository_sha`; it recognizes declaration classes `immutable_subjects`, `configuration_identity`, `stage_scope`, `run_timestamps`, `external_side_effect_policy`, and `source_integrity`. Producer adapters add classes such as `outcomes`, `resource_usage`, `provider_timing`, `quality`, `comparison`, and `external_actions`. A missing required source or measurement is unavailable/incomplete; a content or identity contradiction is invalid. Comparisons report candidate-minus-baseline deltas and preserve `causal_attribution: not_established`.

Crop sidecar paths in the bounded bundle use an opaque SHA-based alias to avoid exposing candidate IDs embedded in output directories. The hash-verified run manifest retains the original relative locator, and the source SHA identifies the exact sidecar bytes.

Repository artifacts describe the revision that produced the collector bundle. Runtime telemetry is derived only from immutable SQLite and retained-artifact snapshots. Each historical metric declares `observed`, `partial`, or `unavailable`; an unavailable metric is a retention gap, not a zero value. The legacy `executive_summary.json` contains historical collector totals for reconciliation and labels that scope explicitly; use the canonical bundle for run results.

Generate a strict review bundle with:

```powershell
$evidenceHeadSha = git rev-parse HEAD
$freshAfter = "<current-run-start-ISO-8601>"
python scripts/quality/collect_cto_review_evidence.py --state-dir state --artifact-dir out --log-dir logs --output-dir docs/CTO_evidence --expected-commit-sha $evidenceHeadSha --require-exact-head --fresh-after $freshAfter --log-corpus-scope representative_report_processing --include-github-status --replace-output
```

To include a retained workload or benchmark, add `--run-manifest docs/quality/<run-manifest>.json`. The manifest names the producer artifacts and their hashes; the collector verifies those bytes and projects supported producer formats without rewriting their source results. Unsupported formats and absent measurements remain explicit gaps. The run manifest and all source artifacts must be inside the repository root.

The GitHub status snapshot is intentionally opt-in because it is an external read. It records the tested revision separately from latest `main`, and returns an explicit unavailable status when it cannot be collected.
