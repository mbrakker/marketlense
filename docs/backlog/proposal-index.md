## Reconciliation policy

- Before implementing a listed proposal, check actual HEAD, reconcile prior commits and tests, and validate its proposed impact and dependencies. If implemented already, record proof and avoid duplicate changes.
- `Scoped implementation reported` is not a completion verdict for the parent. `Proposal` does not assert a still-present defect. `Investigation` should conclude `no change needed` if frozen comparisons cannot justify implementation.
- Keep original technical IDs stable, one primary owner per ID, and links both ways. Do not automatically activate new canonical tasks or override Closed/Deferred/Excluded status from archived research.
- Follow the parent specification's acceptance criteria; close the parent only when its full outcome passes.
